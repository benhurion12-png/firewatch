## Проверено в браузере

- Вход менеджера через настоящий API и HttpOnly cookie.
- Socket.IO через same-origin маршрут /realtime.
- Светлая и тёмная темы; тема сохраняется после перезагрузки.
- Создание лесного участка менеджером.
- Регистрация HMP155 и назначение новому участку.
- Детальная страница с CRITICAL, фактической историей в тестовой БД и графиками.
- Страница всех трёх авторов.
- Семь страниц при ширине 390 px: обзор, участки, датчики, события, авторы, методика, детальная страница. Переполнения по горизонтали нет.
- Выход из аккаунта на мобильном экране.
- Ошибок JavaScript (pageerror) не обнаружено.

Снимки интерфейса сохраняются в локальной папке .test-results:
dashboard-light.png, dashboard-dark.png, area-dark.png, authors-dark.png, dashboard-mobile.png.
Папка не включается в Git.

## Проверено в интеграции

Использовалась отдельная PostgreSQL 17 на 127.0.0.1:55435, база firewatch_test. Существующие базы компьютера не использовались.

26 проверок охватывают анонимный доступ, роли, запрет самостоятельного повышения прав, создание и назначение датчиков администратором и менеджером, запрет второй пары одного типа, дедупликацию messageId, нормальное и критическое состояние, историю, журнал, подтверждение предупреждения без сброса риска, переназначение с сохранением прежней истории, отбрасывание старых пакетов, защиту участка с историей от удаления, изменение ролей действующей сессии и серверный отзыв сессии после выхода.

Телеметрия для интеграции подавалась напрямую в реальный сервис Monitor.ingest, а не через фиктивные ответы API. Для браузера использован отдельный тестовый ui-server.cjs с simulated=true. Он не входит в команды Docker / production-запуска.

## Не проверялось в этом окружении

Docker Engine был недоступен. Поэтому контейнеры Mosquitto / Redpanda и полный транспорт MQTT → Kafka → API в Docker не запускались. Сами нормализатор, обработчик, схема Compose, логика записи в PostgreSQL и живое обновление UI проверены отдельно.

Физические HMP155 / FS24X не подключались. Реальный драйвер аппаратного шлюза зависит от выбранной комплектации и должен реализовать описанный MQTT-контракт.

После проверок временные серверы приложения и отдельная тестовая PostgreSQL остановлены. Рабочий проект запускается через scripts/start.ps1 после запуска Docker Desktop.
